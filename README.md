# Сотки — прототип v0.9

Игра в фишки (caps / pogs) с честной физикой. Клиент присылает только ввод, исход считает сервер,
а любой игрок может перепроверить каждый бросок у себя.

## Запуск

**Демо в одной вкладке** (сервер работает внутри страницы, игра вдвоём за одним экраном):
откройте `index.html` через любой статический сервер, например `npx serve .`.

**Локально с настоящим сервером** (Node 22.13+):

```bash
npm install
npm run dev             # http://localhost:8080/?online=1 — вход без Telegram (DEV_AUTH)
npm test                # сквозной тест сервера + детерминизм и баланс бит
```

Откройте `http://localhost:8080/?online=1&name=Аня` и `…&name=Борис` в двух разных браузерах
(или в обычном и приватном окне): у каждого свой гость.

## Выкладка в Telegram

1. **Бот.** В @BotFather: `/newbot` → имя и username. Токен **никому не пересылайте**, он нужен только хостингу.
2. **Хостинг** (например, Railway): New Project → Deploy from GitHub repo → этот репозиторий.
   Dockerfile подхватится сам.
   - Settings → Networking → Generate Domain — получите `https://…up.railway.app`.
   - **Volume** с путём `/data` — без него база (игроки и фишки) сотрётся при каждом деплое.
   - Variables: `BOT_TOKEN` (из BotFather), `APP_URL` (домен из шага выше).
3. **Mini App** (необязательно, но приглашения станут удобнее): в @BotFather `/newapp` → выберите бота,
   URL = тот же `APP_URL`, короткое имя, например `play`. Добавьте переменную `BOT_APP_SHORTNAME=play`.
   Тогда ссылка-приглашение `t.me/ваш_бот/play?startapp=СТОЛ` открывает игру сразу за нужным столом.
4. Напишите боту `/start` → «Играть». Кнопка «Играть» появится и в меню чата.

Проверка, что сервер жив: `https://ваш-домен/health`.

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен бота — **секрет**, только в настройках хостинга |
| `APP_URL` | публичный https-адрес сервера |
| `BOT_APP_SHORTNAME` | короткое имя Mini App из `/newapp` (необязательно) |
| `DATA_DIR` | папка базы, в Docker по умолчанию `/data` |
| `DEV_AUTH` | `1` — вход без Telegram, **только для отладки** |

## Структура

| Файл | Что делает |
|---|---|
| `shared/sim.js` | Детерминированная симуляция одного броска (Rapier, deterministic build). Один и тот же код на сервере и клиенте |
| `shared/fair.js` | SHA-256, commit-reveal, PRNG sfc32, своя тригонометрия (Math.sin в разных движках может отличаться в последнем бите) |
| `shared/content.js` | Скины фишек, редкость, биты |
| `server/core.js` | Логика партии: ставки, камень-ножницы-бумага, ходы, таймер хода, валидация ввода, перенос фишек |
| `server/rooms.js` | Столы, приглашения, случайный соперник, переподключение (место держится минуту) |
| `server/store.js` | База SQLite (встроена в Node): игроки, фишки, партии, каждый бросок, рейтинг отдельно по режимам |
| `server/auth.js` | Проверка подписи Telegram (initData) — подделать имя или id без токена бота нельзя |
| `server/ws.js` | WebSocket-сервер без внешних пакетов |
| `server/bot.js` | Бот: кнопка «Играть», `/start`, приглашения |
| `server/server.js` | Точка входа: раздаёт клиент, WebSocket, бот |
| `client/app.js` | Three.js-стол, жест броска, реплей, проверка честности, лобби и приглашения |

Единственная внешняя зависимость сервера — физический движок Rapier.

## Как устроена честность

1. Перед ходом сервер генерирует `serverSeed` и публикует только `sha256(serverSeed)` (коммит).
2. Клиент шлёт ввод — целые числа: сила 0–1000, наклон в десятых градуса, направление, прицел — и свой `clientSeed`.
3. Сервер выводит `fairSeed = sha256(serverSeed:clientSeed:turn)`, добавляет «дрожь руки»
   (разброс силы, угла, точки удара), считает физику, переносит фишки.
4. Сервер раскрывает `serverSeed`. Клиент проверяет коммит, повторяет симуляцию и сравнивает хэш
   финального положения всех тел. Совпало — бросок честный.

Против ботов: разброс применяется после ввода и неизвестен до раскрытия сида, поэтому даже идеальный
бот получает распределение исходов, а не гарантированный переворот.

## Управление

Зажмите биту (в режиме «Удар битой») или стопку (в режиме «Стопкой из руки») пальцем или мышью
и тяните **вверх**: объект поднимается вместе с пальцем, выше значит сильнее. Сдвиг **в сторону** —
наклон и смещение удара к краю стопки (удар ребром). Отпустите — бросок. Если опустить палец
почти в исходную точку, бросок отменится. «Вправо» считается относительно камеры, поэтому
направление удара меняется поворотом стола.

## Физика (v0.8)

- 1 ед. = 1 см, g = 981, CCD включён.
- **Жёсткость контактов 120 Гц** вместо 30 Гц по умолчанию. Rapier настроен на тела размером в метры;
  для фишек 2,6 мм контакты были «ватой»: стопка из 10 фишек сплющивалась под весом биты почти
  вдвое, фишки входили друг в друга, и бита «застревала» внутри стопки. Сейчас шаг фишек в стопке
  после удара 0,262 см (ровно толщина фишки), взаимных проникновений нет.
- **Переменный шаг**: 1/960 с, пока что-то движется быстрее примерно 80 см/с (удар), иначе 1/240 с.
- **Два критерия покоя**: скорости почти нулевые или за 0,5 с ничего не сдвинулось больше чем на 3 мм.
  Второй нужен, потому что фишка, опёртая краем на биту, может бесконечно дрожать на месте.
- Упавшие со стола тела больше не учитываются.
- Удар битой: скорость броска около 2,5–11,5 м/с, бита поднимается на 3–12 см.
- Бросок стопкой: каждая фишка отпускается со своим разбросом скорости и вращения.
- Замеры (caps-sim-4): удар ребром — Классика 1,56, Свинчатка 1,38, Блин 1,81 фишки за удар
  (16–20 бросков, разница в пределах разброса). Ровный удар по центру — 0,15. Стопка ровно — 2,05,
  стопка с наклоном — 2,95. Расчёт одного броска 60–140 мс.
- Правило наклона: до 20° чисто, 20–30° предупреждение, больше 30° фол. Фишка на ребре не считается.

## Что дальше

- Проверить детерминизм между разными устройствами (iOS Safari, Android Chrome, Node): `npm test` печатает эталонный хэш.
- Хранилище (Postgres/Redis) вместо памяти процесса, реплеи всех бросков для разбора споров.
- Авторизация через Telegram `initData` (проверка подписи на сервере).
- Фишки как NFT (TON, TEP-62), покупки за Telegram Stars.
- Юридическая проверка модели «игра на фишки с денежной ценностью» до запуска токена.
